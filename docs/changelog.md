# 用户更新记录

返回 [README](../README.md)。

## 0.5.0（2026-11-12）

配套：记忆插件 [dsh-memory-starter](https://github.com/XRH66/dsh-memory-starter) 0.5.0、人设插件 dsh-global-settings 0.2.0（不变）。固定提交见[安装说明](setup.md#3-安装插件)。适配 DSH 0.2.1-rc.5。

- 向量索引按模型分档案保存：换检索模型不再清掉旧索引，切回来复用原档案、只补差量；「检索模型」页可查看和切换各档案。
- 「维护 → 删除原话」：按关键词找到某段原话并撤回，向量索引同步更新。
- 「维护 → 旧记忆迁移」：把 0.3.0 旧库里的旧笔记一次性整理成新格式条目，后台自动跑，可暂停、继续，拿不准的进「待确认」；旧文件不改。
- 接口向量服务显示实际使用的维数，可为支持的模型选择「向服务商请求这个维数」。
- 记忆插件内部精简：去掉不再使用的旧整理器、旧召回链和 Basic Memory 回退。插件配置里写了 `sessionMemory: false` 的会启动报错（本仓库生成的配置不写这一项，不受影响）；没有整理模型时只保存原话。
- 从 0.4.0 升级只需换插件提交，见[升级说明](upgrade.md)。

## 0.4.0（2026-11-11）

配套：记忆插件 [dsh-memory-starter](https://github.com/XRH66/dsh-memory-starter) 0.4.0（原名 dsh-basic-memory-bridge）、人设插件 dsh-global-settings 0.2.0。固定提交见[安装说明](setup.md#3-安装插件)。适配 DSH 0.2.1-rc.5。

- 记忆插件改为新架构：按对话开启、原话库、模型按需检索（`memory_search`／`memory_open`／`memory_recent`）、后台整理为十二类条目、按类型的遗忘曲线、跨对话短期接续、可选向量检索（本地 Qwen3-Embedding 或 OpenAI 兼容接口）和可选重排。
- 不再需要 Basic Memory、它的 MCP 连接、会话设置插件和纯净模式插件；记忆插件的首次配置在「记忆框架」页面完成。
- 配置生成器只生成部署路径和人设插件配置；启动脚本不再设置 `DSH_MEMORY_VAULT` 和 `BASIC_MEMORY_CONFIG_DIR`。
- 删除第三方 Agent 通过 Basic Memory 共享记忆的路线、旧库迁移指南和 0.3.0 介绍稿。工程控制附录保留。
- 0.3.0 的旧库可以在「维护 → 记忆库」里直接选用，旧笔记按原样读取，见[升级说明](upgrade.md)。

## 0.3.0（2026-10-29）

文档补充：区分本方案版本与DSH宿主版本；0.2.2-alpha.2尚未适配。统一手动重启约定、第三方补丁边界和小黑盒介绍，未改变运行代码。

配套：记忆桥 0.2.0、全局设置 0.2.0、独立纯净模式插件 0.1.0。固定提交记录在本仓库 0.3.0 发布提交 `0f37aeb` 的 `docs/memory.md`。

- 新增按会话纯净开关：可在新对话第一条消息前开启，暂停个人注入与相关工具；不改 MCP 勾选和工程规则，不清除既有聊天。
- 近期聊天缓存支持跨会话接续；只收集直接用户与最终助手文本，从升级后的新交流开始滚动积累，不是把全部缓存每轮塞给模型。
- 现有多路召回统一去重与正文预算；旧自动注入在下一轮从模型视图移出，原始聊天仍保留。
- 同范围最新明确要求作为当前值，旧要求独立保留历史；临时要求不改长期偏好。
- 原记忆面板增加分环节用量、召回来源、预算/去重与队列状态；旧回合缺用量时显示未知。
- 修正旧自动块清理的事件时序，并核验原生严格日志恢复。已经损坏的日志仍需定向诊断，升级不会自动修好所有旧日志。
- 增加先升级基础设施、再整理旧库的指南和手动重启续接模板；无 Codex 的 DSH 用户也能按步骤执行。

遗忘、索引、持久补写与强化在旧版已存在，本版延续这些机制。标准原生工具模式 + High 的隔离验收覆盖长期召回、后台纠正/写入与跨会话接续；不据此承诺长对话速度或普遍准确率。验证边界见 [验证说明](validation.md)。

第三方 GenUI 按需说明与 billion-context 符号流补丁单列于 [可选组件](optional-components.md)，不是本项目自研或必装组件。

## 0.2.0

默认路线改为独立 DSH 记忆与人设，不要求 Codex；增加第三方 Agent 通过同一 Basic Memory MCP 维护个人库的说明。工程控制仍是可选路线。
