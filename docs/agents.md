# 可选：第三方 Agent 软件协作维护记忆

返回 [README](../README.md)。先按[默认安装](setup.md)建立DSH记忆与人设。这条路线让其他支持**stdio MCP**的Agent软件接入同一个Basic Memory项目，不要求Codex，不需要 `dsh-mcp-control` 或派工CLI。

## 接入同一套记忆

使用默认部署生成的 `basic-memory.mcp.json`，把其中的服务器配置导入第三方软件的MCP设置。不同软件的配置入口、外层格式可能不同，应按该软件说明填写；核心参数保持一致：

```json
{
  "mcpServers": {
    "basic_memory": {
      "transport": "stdio",
      "command": "basic-memory",
      "args": ["mcp", "--project", "personal"],
      "env": {
        "BASIC_MEMORY_CONFIG_DIR": "<现有部署的basic-memory-state绝对路径>"
      }
    }
  }
}
```

生成文件中已填入实际路径，不要把上面占位符原样导入。若第三方程序找不到 `basic-memory`，将command改为 `Get-Command basic-memory` 返回的绝对路径。保持与DSH一致的配置目录、项目名和Vault；不要新建同名但指向另一份数据的项目。

stdio客户端在同一台电脑启动本地Basic Memory进程，多个连接访问同一项目；它们不需要共享DSH会话控制token。云端Agent或另一台电脑无法直接使用这份本地路径，本方案没有配置公网服务或跨机器同步。

先在客户端确认出现 `search_notes`、`read_note`、`write_note`、`edit_note` 等工具（有的软件加 `mcp__basic_memory__` 前缀）。可以先只启用查询工具，再按实际维护任务开放写入；客户端工具开关不是Basic Memory服务端的权限隔离。

## 分工与适合的任务

| 使用方 | 职责 |
| --- | --- |
| DSH和记忆桥 | 日常聊天、自动召回与轮后整理、纠正、索引及遗忘强化 |
| 第三方Agent | 按用户任务检索、核对来源、补充资料、纠正已确认错误、提出重复条目整理方案 |
| 用户与Obsidian | 直接查看笔记、审核修改、决定归档或删除 |

其他Agent只接入Basic Memory，不会自动获得DSH桥的全部生命周期。它的每次聊天不会自动被桥捕获，也不会自动固定注入DSH人设或自我档案。DSH中已有的外部编辑同步按桥支持的范围工作，不能承诺第三方任意改写都能自动修复所有索引与历史。

## 可复制给第三方Agent的维护约定

> 你接入的是我在DSH里使用的同一个个人记忆库。默认先检索并阅读相关笔记，再处理我当前指定的维护任务。
>
> 事实必须有明确来源；区分用户事实、外部资料和助手自己的推测。不得把测试内容、工程日志或猜测当成真实用户经历。
>
> 修改前读取最新正文，尽量局部编辑。保留稳定ID、permalink、来源、日期、历史、权重和管理标记；对于不理解的托管段先提出修改建议。支持校验和的写入使用最新checksum，遇到冲突重新读取，不覆盖他人改动。
>
> 同一篇笔记一次由一个客户端修改，尤其避免DSH正在整理时由另一Agent整篇覆盖。每次写入后重新读回，报告具体改了什么。
>
> 合并、归档、删除先给我审阅；不要直接操作数据库、批量删除笔记或绕过DSH里的删除限制。维护范围以我本次要求为准，不把整个记忆库无差别读入上下文。

## 验证共享是否成功

在独立测试库中，由一端通过MCP写入带明确测试标记的虚构笔记；结束这个连接后，从另一端搜索并读回，同时在Obsidian核对同一文件。看到相同正文才能确认共用同一库，工具出现不等于路径一致。

本项目已做真实MCP跨进程写读与检索测试；未逐一验证所有第三方Agent软件的UI、权限设置和模型行为。每种客户端首次接入仍需核对实际工具和数据位置。

这是一个人的多个客户端协作，没有多用户权限与隐私隔离。接入者可能获得库内全部内容；模型调用时读取的笔记可能发送到该客户端选择的供应商。只接入你信任的客户端，并按任务限制读取范围。

## 额外的工程控制

若还需要第三方Agent向DSH派发代码任务、续接会话、读取执行结果，再选择[工程控制附录](control.md)。那是额外的会话控制权限，并非协作维护记忆的前置条件。

## 升级和旧库维护

用户可直接把 [升级指南](upgrade.md) 交给自己的 DSH，无需 Codex。先完成版本/路径发现、一致备份和基础设施验收，再按 [旧库整理](memory-migration.md) 生成该用户自己的语义计划。当前要求按来源语义时间及同范围最新明确要求判断；保留旧历史、身份、日期、权重、半衰期、强化记录与遗忘基线，临时要求不覆盖持续规则。

批量外部修改前隔离后台，使用当前桥的观察器机制防止重复 CORRECT 和强化，保留队列；维护读写本身不强化。纯净模式拒绝记忆工具时先取得明确本地维护或独立隔离维护进程授权，不绕过工具限制。

凡需重启，说明受影响会话、保存 [本地续接记录](../examples/upgrade-progress.md) 并暂停，由用户知情后手动重启。恢复后先读记录、核对实际加载和会话接口，再继续；Agent 不自动 restart。
