# 升级到 0.3.0：交给自己的 DSH 执行

返回 [README](../README.md)。本指南可交给你自己的 DSH，不需要 Codex。执行者先读取本页，只做已获授权的本地升级；它不是一键迁移器。旧库整理是独立的第二阶段，不随插件升级自动执行。

## 版本与边界

本次发布为主仓库 0.3.0、记忆桥 0.2.0、全局设置 0.2.0、[纯净模式](https://github.com/XRH66/dsh-pure-mode) 0.1.0。配套固定提交见 [安装说明](memory.md)，已核对公开仓库；与包版本不符时停在安装前。DSH / Basic Memory 的适配基线见 [验证说明](validation.md)。

升级保留用户自己的 MCP、模型服务、权限、人设、自我档案和 AGENTS。只合并已核对的新插件项与必要配置，不整份覆盖现有配置，不运行 configure 覆盖旧目录。GenUI / billion-context 是独立可选补丁，见 [可选组件](optional-components.md)，不混入必需升级。

## 阶段一：发现、备份、安装与基础设施验收

1. **发现实际安装。** 读取本机命令解析结果、DSH 与 Basic Memory 版本、实际加载插件版本/位置和启动参数。找出当前 profile、DSH home、配置与补丁、Vault、Basic Memory 配置与 SQLite 数据库、桥 management、近期缓存、队列及遗忘基线。记录会话运行/排队/待批准情况。路径来自本机现有配置，不能照抄别人的部署。完成条件：每个待改对象与正在使用它的进程对应明确；不明对象保持只读。
2. **备份可恢复状态。** 将代码、配置、Vault、管理状态、人设与自我档案、必要的原始来源备份到仓库和 Vault 外，记录版本、哈希与时间。SQLite 必须使用在线一致快照（SQLite backup API / 官方备份入口），或在所有写入停止并核实连接状态后复制；禁止直接生拷活跃数据库，尤其不能只复制 WAL 模式的主 db 文件。检查快照 quick_check，记录文件备份期间的写入变化；数据库快照与 Markdown 不是跨系统原子快照。发现变化就协调停写并补备份。完成条件：备份可读、检查通过、恢复对象清楚。
3. **优先准备纯净开关。** 先安装经版本核验的纯净插件；已有实例需要重载/重启时执行下方暂停协议。插件可用后，新建空白对话，在第一条消息前打开纯净模式，再把本指南和本地进度记录交给该对话。旧上下文不会被抹掉，不能在原长聊天点一下就称为全新纯净。旧桥可能仍持有后台任务或旧作用域，纯净开关不能替代后台隔离：检查并显式暂停/隔离旧桥自动写入、纠正与索引维护，保留队列，不删任务。不能可靠隔离就停在写操作前。
4. **更新配套插件。** 在隔离副本验证桥、设置和纯净插件的版本组合；用本机实际 profile 的插件管理入口安装核对过的版本，按差异合并配置，保留 MCP 勾选、供应商、AGENTS 和个人内容。生成器只服务全新独立部署。近期缓存从新消息积累，不导入所有旧聊天。任何所需重启均走暂停协议。
5. **核验真实生效。** 用户手动重启后先读续接记录，再比较实际进程、插件加载版本/代码指纹与目标；验证真实会话状态/历史接口，不只看 health=ready。确认新纯净会话的个人工具受限、个人注入关闭且原 MCP 配置未改；普通测试会话按原配置可用。核对队列、遗忘基线和保护文件未重置；只在授权的独立测试库验证写入、搜索与读回。模型验收需另有调用授权，不能向正式聊天灌测试内容。完成条件：加载、作用域、路径、状态保护及本地接口验证通过，未验证项明确记录。

阶段一通过后才提出 [旧库整理](memory-migration.md)。没有需要整理的旧库可在这里结束；安装成功不代表所有语义记忆已修好。

## 检查旧 profile 的显式捕获上限

源码默认值变了，旧 profile / patch 中显式配置不会自动跟着变。检查记忆桥实际生效配置；旧版可能仍有 `captureTimeoutMs: 20000`、`captureMaxTokens: 1024`。向用户展示逐项差异及来源：新版默认是 `captureTimeoutMs: 90000`、`captureMaxTokens: 8192`，用于后台提炼/纠正的最大等待和最大输出预算，完成即返回；不是每次固定等待90秒或固定消耗8192 token，也不是前台召回预算。

区分沿用旧默认与用户有意自定义值。仅在用户同意升级默认行为的授权范围内合并这两个相关字段（或按当前配置层级移除旧覆盖以继承新版默认）；保留有意自定义及其余配置。记录修改前后实际有效值，不能只检查源码常量，也不能整份覆盖 profile。若需要重启仍走下方暂停协议。

## 每一次重启都必须暂停

执行者先说明将影响哪些运行实例、聊天、工程会话、后台整理及可能未保存内容，核实可暂停状态；把当前步骤、已改文件、备份、队列状态和下一步写入仓库外的 [续接记录](../examples/upgrade-progress.md)。然后停止操作，明确等待用户在知情下手动重启。

Agent 不得调用自动 restart、stop/start、强杀再拉起或电源插件来替用户重启，也不把“用户授权升级”解释成自动重启许可。用户完成后，新/恢复的 DSH 先读取记录并核验进程与会话接口，再从下一未完成步骤继续。若仍运行旧代码，报告事实并保持暂停，不反复重启。

## 纯净模式下的维护权限

纯净模式会挡 Basic Memory 与个人记录工具。确需读写库时，先取得用户明确的本地维护授权，或由用户授权一个单独、隔离的维护进程，说明路径与写入范围并记录授权。没有授权就输出待审方案并暂停。不指导换工具名、借子代理或用文件/数据库入口绕过工具限制；纯净模式不是文件系统沙箱，文件权限也不等于本次维护授权。

## 失败与恢复

先停在当前失败步骤，保存错误和已完成结果。恢复按变更清单逐项比较后回退，不用整库旧备份覆盖升级后新增记忆。恢复若需重启仍执行同一暂停协议。日志损坏需结合目标宿主格式做专门诊断，不能套用他人的私人一次性日志修复脚本；恢复后检查原会话历史及旧页面已有消息可见性。
