# 旧记忆库整理：按自己的来源生成计划

返回 [升级指南](upgrade.md)。只有阶段一基础设施验收通过，且用户明确授权旧库维护后才执行。你自己的 DSH 可完成这些工作，无需 Codex。公开包只提供通用流程，不含任何人的条目清单、备份、固定路径或迁移脚本；不承诺读完指南就能一键完美整理。

## 1. 确定本地基线

复用升级记录，再确认真正的 Vault、数据库、管理目录与索引项目。按升级指南制作一致 SQLite 快照和文件备份，安排后台停写；任何重启先写续接记录并等待用户手动完成。保留原队列、失败退避/暂停状态、检查点与遗忘启用基线。纯净模式挡维护工具时，必须先有明确本地维护授权或单独隔离维护进程授权，不能绕过限制。

列出本次相关条目、稳定 ID / permalink、来源、发生日期、首次记录日期、范围、当前值、历史、权重/半衰期/强化记录、引用和哈希。清单仅保存在本机 Vault 外。保护用户指定原文、人设、自我档案、AGENTS 及无关内容。完成条件：计划内每项都有可核对来源，缺失信息标为未知。

## 2. 根据语义与来源时间判断当前要求

对每位用户自己的来源逐项判断说话者、主题、适用范围和语义时间。同主题、同范围的最新明确持续要求为当前值；不同范围可以并存，一次性任务或临时例外不覆盖持续要求。文件 mtime、导入时间、索引刷新时间不能代表用户改变主意。来源时间不明、转述不明确或互相冲突的内容进入待审，不靠猜测选最新版。

例：来源先说“日常回复简短”，后来明确说“日常长短自行决定”，更新同一当前要求，旧句独立保留为历史；“这次只答一句”不替换长期偏好；“工作评审要详细”属于另一个范围。复合要求仅修改被明确改变的部分。助手推测与建议不能升级为用户事实。

同一逻辑要求继续使用原稳定 ID，先保存完整旧版本及来源，再更新当前值和历史链接；普通召回面向当前，明确追溯时才读历史。使用目标桥现有的范围与历史格式，不另造并行数据库。完成条件：每项当前/历史关系有证据，待审与确定项分开。

## 3. 保留遗忘与强化语义

保留稳定 ID、原始发生日期、首次记录日期、条目标记、权重、半衰期、上次强化时间与强化历史；未知日期仍未知。阅读、迁移、重建索引、助手自我修订都不是新的用户交流，不增加强化。

目标记忆桥0.2.0的 `lib/priority.js` 已核对的缺省解释如下；这是运行时解释，不要求给旧文件批量补写字段：

- `base_priority` 缺省为1，半衰期缺省30天，底值为0.01；已有显式权重、半衰期及强化历史继续保留。
- 衰减起点优先采用已有显式 `decay_anchor_at` / `softened_at`；没有显式起点时，使用自然遗忘启用基线 `naturalDecayStartedAt` 与可信 `recorded_at` 中较晚的时间。
- 不按文件 mtime 追溯老化，不把导入、迁移或索引刷新当天伪装成首次记录时间；日期缺失或不可信时保持未知，不补造日期。
- 无权重字段不须批量填权重。已有 `naturalDecayStartedAt` 基线绝不重置，整理、重启或升级都不重新起算；备份与恢复须保留该基线。

后续版本若改变上述实现，才重新核对对应解释。旧版已经有遗忘、索引与强化，本次是延续和改进，不是首次引入。

## 4. 隔离演练与副作用控制

先在副本按计划执行，使用真实 Basic Memory 索引和读回接口。只有同 ID、同来源、同正文与同时间且确认同一逻辑记录的精确副本才能提出合并；相似文字或同名人物不够。默认不物理删除；疑似重复与删除/归档建议放 Vault 外待审，经明确授权的副本归档也保留原字节与位置映射。

更新事实时同步索引、物理链接、permalink（含 URI 编码隐藏引用）、入链和历史引用，去掉合并造成的完全相同引用；合理人工摘要不按字符串差异强行重写。修改后的文件必须能被真实搜索找到，移出副本的旧精确地址应不再命中。

外部修改托管 value 可能触发新一轮 CORRECT 及档案修改。正式落盘前隔离桥后台；复用当前版本已有观察器逻辑，仅为这批已经同步完成的修改更新观察基线，避免重启后再次纠正或重复强化。不能清空恢复文件/队列，也不能让仍持有旧缓存的进程继续写。没有受支持入口或无法验证观察基线时，暂停实施并报告缺口，不盲改管理 JSON。完成条件：副本索引与读回、引用、元数据保护、副作用控制均已验证。

## 5. 按计划落盘与验收

落盘前再次比较来源文件哈希；有并发改动就重读并重做相关项。只应用已审定差异，先历史后当前再索引。记录逐项结果及恢复路径，不把未处理项写成完成。

恢复后台前确认观察基线、原队列与遗忘基线一致；重启按升级暂停协议。随后用目标真实 MCP 搜索/读回检查当前值与历史，核对重复 ID、重复 permalink、断链和保护元数据。Obsidian 缓存变化单独解释，不能覆盖用户的新布局。观察恢复后不会重复纠正/强化；无模型授权时只验证本地行为并标注未做自然聊天验收。

完成报告说明改了哪些确定项、哪些仍待审、哪些仅做结构验证；不以笔记数量下降代表质量提升。回滚逐项比较后恢复，不覆盖此后新增内容。进度与重启续接沿用 [同一模板](../examples/upgrade-progress.md)，不公开本地记录。
